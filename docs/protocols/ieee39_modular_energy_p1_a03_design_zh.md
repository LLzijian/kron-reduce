# P1-A03 方案：无损保存旧证据

状态：A03 执行方案；正式登记以 harness 的独立运行及冻结副本为准，不构成科学接受。
分支：`codex/loop-p1-a03`。起点：A02 失败源码快照 `93d29d9`，不是已接受模型。

## 问题与原则

A02 在真实候选获取时，因旧结构结果含 `margin: NaN` 而无法写入严格 JSON。
旧文件是不可修改的证据，字段未定义不能被改为零、当作稳定裕度或藏入成功统计。
迁移的任务只是保存与索引旧证据，不是重新解释旧实验。

因此把两个不同职责分开：原始科学结果按字节复制；单模型声明和引用关系写进新的
严格 JSON 文件。旧原始文件可以保留历史格式，新的说明文件不能使用 NaN/Infinity。

## 拟定工件

1. `legacy_structure_selection_result.json`：从旧运行原样复制，复制前后 SHA256 必须一致。
2. `candidate_structure_selection_explicit.json`：仅包含单模型数量、无路由声明、旧文件路径与
   SHA256、迁移方式和结论限制；不展开旧指标，不复制或重算旧稳定标签。
3. `legacy_format_audit.json`：记录旧文件是否含未定义数值、对应字段路径及处置方式
   `preserved_in_legacy_payload_not_claimable`。不得输出非有限 JSON 数值，也不得将其替换成
   有效数字或把缺值等同于“认证稳定”。
4. `artifact_hashes.json`：覆盖整个新运行的所有普通文件；原始文件与说明文件都必须登记。

说明文件使用 `kron_reduce.legacy_structure_envelope.v1`，格式审计使用
`kron_reduce.legacy_json_format_audit.v1`。未定义值用 JSON pointer 和字符串种类索引；
字符串内容恰好是“NaN”不视为未定义数值。重复 JSON 键含义不唯一，必须拒绝。
新说明不能新增科学指标或删除已发现的未定义值记录；核验时从冻结原文件重新生成预期说明并比对。

旧 `validation_summary` 和 `lineage` 是补录单模型、无路由声明的依据。如果它们冲突、字段
缺失或旧结构已有相反声明，应拒绝获取；不能强制覆盖成期望值。

## 执行顺序与验收

1. 绑定 A02 负记录及其哈希，创建 A03 配置和工作流，保持 F1、seed 324、五臂及数值门不变。
2. 新增回归：真实旧结构文件的只读迁移、嵌套 NaN/Infinity、字段矛盾、原文件或引用哈希被
   改动、冻结后新增文件，以及 test/F2--F5/未来机械功率输入越界。
3. 真实文件回归只读取已保存的旧工件，不访问原始轨迹；不能把“能读取文件”写成模型可复现。
4. 静态检查、测试和数据审计通过后，按 harness 登记新的 `plan_registered`、`candidate_acquired`。
5. 交叉核验新候选、历史方案、旧基线及模型文件的哈希和声明。成功只表示候选获取完成。
   该核验必须在候选执行器返回之前完成；写出文件本身不等于本阶段通过。
6. 失败则保留新失败运行和负记录，不重跑覆盖，不放宽严格 JSON，不晋级模型。
