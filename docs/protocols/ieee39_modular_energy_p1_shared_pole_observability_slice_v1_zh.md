# IEEE39 模块化能量 P1：共享方程极点与局部可观测性冻结协议

版本：`ieee39_modular_energy_p1_shared_pole_observability_slice_v1`。本协议属于
P1 A03 的模型单元门证据片段，只回答“冻结模型的哪些方程极点能在已登记激励中
被局部观测到”。它不执行新的 IEEE39 拟合，不改变工作流状态，也不产生模型晋级
或论文级频率结论。

## 1. 第一性原理与本轮假设

振荡频率若要成为模型结论，必须是一个明确动态方程在平衡点附近的极点。轨迹
DMD 只描述有限窗响应中出现了什么，既不能创造模型极点，也不能把受迫、非线性
响应自动解释成系统本征频率。因此本轮严格分成两条不反向连通的路径：

1. 从冻结的第三臂因果模型及其平衡静态量计算一次共享方程谱；
2. 在模型和共享谱完全冻结后，按已登记激励视图读取 internal-audit 速度轨迹，
   只判断每个共享极点在该视图中是否可见。

本轮适用一个额外、可证伪的假设：所有 internal-audit 事件的 `mass`、`incidence`、
`equilibrium_delta` 和 `Pm_equilibrium` 经 float64 规范化后必须逐字节相同。当前冻结
角色的只读静态审计满足这一条件。若任一量不同，本轮返回 `INVALID_STATIC_FAMILY`；
不得利用轨迹 DMD 将不同运行点的极点事后聚类。运行点变化必须新开“方程极点分支
延拓”协议。

## 2. 冻结输入、访问边界与父工件

- 模型唯一来源是已校验五臂父工件的 `core3.npz`，即
  `current_zoh_balanced_loss`；先校验五臂工件清单、父 manifest、第三臂 checkpoint
  哈希和角色 manifest 哈希。
- 只允许读取完整 F1 `internal_audit` 角色；test、F2--F5、external validation、
  post-freeze safety 角色均保持锁定。
- 模型输入仍只有登记的平衡静态量和因果 `Pm_clear` ZOH。来源名、故障线路、事件
  名、未来 `Pm`、`Pe`、电压、稳定标签、有效长度和事件时间不得进入模型或方程
  极点计算。
- `source_dataset` 和 `fault_line` 只能在共享谱冻结后用于局部观测分组和线路级
  bootstrap；它们不改变模型、极点、DMD 参数或匹配门槛。
- 不读取 v8 checkpoint 作为模型输入。v8 的普通 DMD 和 observed-`Pm` DMDc 仅作为
  历史负证据：它们没有形成共享模态晋级，不能被改写成新模型的极点来源。
- 本轮不拟合、不重拟合、不选超参数、不估计损失尺度，也不改变任何父工件。

## 3. 共享方程极点

先对四个平衡静态数组做形状、有限性和逐字节一致性检查，并记录共同静态签名。
只有检查通过，才从按事件 ID 排序后的第一个静态副本调用
`PrunableEnergyModel.modal_spectrum`。极点计算固定为：

- 频率范围 `0.05--5 Hz`；
- 平衡残差无穷范数不超过 `1e-7`；
- 储能 Hessian 正定；
- 能量归一化速度可见度不低于 `1e-3`；
- 输入--输出留数秩大于零；
- 只保留正虚部、诊断完整的 `equation_reportable_modes`。

所有内部极点和拒绝原因都保存，但只有上述方程可报告极点可进入局部观测审计。
共享极点 ID 由第三臂 checkpoint 哈希、共同静态签名、排序后极点序号及其复特征值
共同确定。轨迹结果不得增加、删除、合并或移动共享极点。

## 4. 轨迹局部观测算法

### 4.1 预登记视图与统计单位

激励视图固定为角色 manifest 中已有的 `source_dataset`，不得按结果拆分或合并。
独立统计单位为 `(source_dataset, fault_line)`。同一线路的多个清除时间是重复事件，
不能增加独立线路数。

### 4.2 有限窗与坐标

每个事件使用完整登记的 `0--10 s`、`dt=0.01 s` 速度轨迹。先转换为
`sqrt(mass) * omega` 的质量加权 COI 坐标，再逐通道减去该有限窗均值。不得使用
未来 `Pm`、标签或其他目标通道辅助模态提取。

对共享极点的质量加权复速度振型，取其实部和虚部张成的实子空间并正交化。有限窗
能量占比定义为速度轨迹投影到该子空间后的平方能量与总平方能量之比；总能量为零
时占比记为零，不得用归一化制造可见性。事件门槛为能量占比不低于 `0.01`。

### 4.3 多秩 DMD 与一对一匹配

普通 exact DMD 仅作为经验响应描述器。每个事件固定计算 rank `4、6、8` 三个版本，
频率范围同为 `0.05--5 Hz`；不根据结果改变秩、时间窗或滤波。每个秩内，全部共享
极点与全部经验模态用 Hungarian 一对一匹配，代价为

`频率相对误差 / 0.05 + 阻尼绝对误差 / 0.05 + (1 - MAC) / 0.20`。

匹配后再应用硬门：频率相对误差不超过 `0.05`，阻尼绝对误差不超过 `0.05`，
复 MAC 不低于 `0.80`。一个经验模态在同一秩中不能支持两个方程极点。某个极点在
至少两个登记秩上通过，才算该事件的经验匹配通过；没有经验模态是诚实的“不支持”，
不是数值补零。

事件支持必须同时满足：共享方程极点有效、平衡/储能/留数秩/速度可见度门通过、
有限窗能量门通过，以及三秩中至少两秩匹配通过。逐事件保存全部候选和匹配，不能
只保存通过者。

### 4.4 线路与 bootstrap

一条线路的支持率等于该线路支持事件数除以完整登记事件数；线路支持门固定为
`>= 0.50`，沿用 v8 已登记的事件比例语义，但使用本轮更严格的方程极点来源和匹配
门。任何失败或缺失事件都保留在分母中。

每个视图固定执行 2000 次、seed 324、以独立故障线路为单位的有放回 bootstrap。
每次计算重采样线路中的支持线路比例，并记录：

- 原始线路支持率；
- bootstrap 2.5%/97.5% 分位区间；
- `bootstrap_support_probability`：重采样支持率不低于 `0.80` 的抽样比例。

视图只有在独立线路数不少于 3 且
`bootstrap_support_probability >= 0.80` 时才通过。少于 3 条线路必须先返回
`UNDETERMINED`，即使原始支持率为 100%。合法 bootstrap 未通过则为
`UNSUPPORTED`；协议、父工件、静态或数据合同破坏则为 `INVALID`。

一个共享极点只需在至少一个预登记视图中得到 `SUPPORTED`，即可记为本轮
`LOCALLY_OBSERVED`。若至少一个视图样本充分但全部不支持，则为 `NOT_OBSERVED`；
若所有视图都因线路不足而未定，则为 `UNDETERMINED`。该状态仍只是 P1 单元证据，
不等于五折核心模态或论文级频率主张。

## 5. 合成已知真值门与对抗测试

在接触新的 IEEE39 模态结果前，算法必须先通过已知线性振荡系统：

- 恢复登记的频率、阻尼和复振型，并使被充分激励的真值极点通过；
- 同一模型的不同激励可分别支持不同极点，最终仍是同一共享极点集合；
- 未激励极点、同频但错误振型、单线路 100% 支持均不得通过；
- 一个经验模态不得同时支持两个方程极点；
- 零能量、零端口、微小可见度、非平衡点、非正定储能和 DMD 数值失败不得被
  归一化或删样本后伪装成支持；
- 打乱事件顺序不得改变结论，复制同一线路事件不得增加独立支持，删除失败事件
  必须被合同拒绝。

合成门只能证明审计算法按设计工作，不能替代 IEEE39 模态证据。

## 6. 不可变工件与验收边界

成功执行时必须一次性写入并封存：

1. `shared_equation_poles.json`：父哈希、共同静态签名、全部内部极点、方程可报告
   极点及拒绝诊断；
2. `modal_event_matches.csv`：每事件、每共享极点、每 DMD 秩的候选、匹配与失败；
3. `modal_line_support.csv`：完整事件分母、线路支持率和线路结论；
4. `shared_pole_local_observability.csv`：逐极点、逐视图的线路数、原始支持率、
   bootstrap 区间、支持概率和状态；
5. `modal_bootstrap.json`、`modal_audit_summary.json`、`lineage.json` 和严格工件哈希。

若执行中断，写 `FAILED.json`，不得写成功 manifest，也不得覆盖失败目录。所有摘要
固定记录：`scientific_verdict=null`、`model_unit_gate_passed=false`、
`promotion_decision=KEEP_BASELINE`、`test_ids_read=[]`、`other_folds_read=[]`。

本片段成功只表示实现和证据链有效。P1 的共享模态单元门仍需与五臂轨迹、模块
效应、可辨识性、物理数值门、历史连续性回放和独立对抗审查共同验收后才能前进。
