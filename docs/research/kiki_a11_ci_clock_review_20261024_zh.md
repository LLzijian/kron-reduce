# A11 CI 时钟测试补充审核

日期：2026-10-24。审核：Astra Ultra。结论：**批准本次仅测试预期时钟的修正，原科学实施审核继续有效。** A11 真实执行仍须等待修正提交的远端 CI 全部通过及执行前冻结检查；本补充没有运行真实拟合、预测或 RHS。

## 已核实的问题

首次远端 CI 的完整测试任务报告 279 项通过、1 项失败，失败发生在首个历史 RK4 子步第三阶段状态的 `torch.equal` 断言。原始日志保存为 `scratch/one_off/kiki-a11-20261024/ci-push-40074960465-failure.txt`，SHA256 为 `98ea78705f5660acfa023c6fe8040e7cc2b0a389db0a3e4f5af8628e21effefc`，不覆盖或删除。

实际 fitter 始终使用每个样本的 `np.diff(history.time)`，再按冻结的两个子步取一半；旧测试却用十进制常量 `0.005` 重建阶段。当前合成时钟首间隔的一半为 `0x1.47ae147ae1478p-8`，常量为 `0x1.47ae147ae147bp-8`，差为 −2.6020852139652106e−18，即该量级的 3 ULP。ULP 是相邻浮点数之间的间距。阶段状态最终是否出现逐位差异还取决于当时状态和斜率，不能由某个平台偶然通过来证明两个步长逐位相同。

因此应修正测试的预期输入，使它独立读取每个合成样本的实际历史时钟；不应改变生产积分器去迎合常量，也不需要放宽状态比较容差。

## 修正范围与验证

`tests/test_temporal_training.py` 仅把 `substep = 0.005` 替换为 float64 的 N×1 张量，其第 i 行为 `np.diff(samples[i].history.time)[0]/2`。所有 RK4 阶段和终点的 `torch.equal`、事件 RHS 预算、更新数和 trace 断言原样保留。修正后的预期仍逐位核验原 RK4 公式，同时正确支持每个事件自己的真实浮点时钟。

新测试文件 SHA256 为 `642f6f28822285a022e088e1625b4b72f60b7f562957cbde1e0bfc90236b4bdc`。本审核将该唯一替换还原后重新计算 SHA，精确恢复旧测试哈希 `4d8e2e5142c1d9f02f62a629f20c0d5e2592d86cc5c7e805eb984302ff565274`，确认没有其他测试更改。审核者独立运行该文件的合成测试得到 `7 passed in 9.73s`，lint 返回 0。
