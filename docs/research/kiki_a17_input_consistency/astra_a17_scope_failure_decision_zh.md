# A17 范围失败与重试尝试的边界裁决

2026-10-25，Astra Ultra。补充接口审核 v1 的 B07；原报告保持不变。本裁决只确定错误处理规则，不批准当前实现或真实执行。

**选择 A：局部数值失败可按失败状态结束；失败后再次尝试同一 scope 的调用，必须停止整轮。**

正常的局部数值异常是已登记计算可能产生的科学结果。当前 scope 立即锁定，保存原始异常、已返回值、部分结果和实际计数；没有再次调用时，可完成 durable failed closure，并开始下一独立 scope。失败槽及其原权重保留，后续依赖按协议记录为 prerequisite_failed。

锁定后再次进入 `call` 则是违反不得重试规则的调用请求。必须在 callback、operation index 和 attempted/returned 计数变更前拒绝，并将整个 journal 永久标记为 poisoned。它不能使用会被正常局部数值失败处理器捕获并继续的异常类型。

此后 `call`、`begin` 和正常 `persist_and_finish` 均不得恢复。仅独立的全局失败收尾路径可以保存已经存在于内存中的证据，并释放资源；不得再次计算、重新读取或补写正常 failed closure 后继续下一 scope。若独立保存也失败，保留已落盘前段及未闭合状态，不声称正常完成。

审计应区分：新调用请求被拒绝、callback 没有执行、没有增加科学操作计数；与整个活动范围未正常闭合、预算已消费且不可重试。`unknown/spent` 描述的是中断范围的闭合状态及预算权限，不能据此虚构一次实际科学调用，也不能覆盖已经知道的 attempted/returned 前段。

修复的定向合成回归至少覆盖：

1. 局部数值异常后未尝试再次调用，原始部分结果可保存、failed closure 可完成，下一独立 scope 可开始。
2. 同一异常后再次调用任意类别或新 index，在 callback 执行前拒绝；实际计数不变，journal 永久 poisoned。
3. 上述拒绝后，正常保存闭合、begin 和 call 都被拒绝；不得因换 scope 名称恢复。
4. 独立全局失败收尾仍能取得原始数值异常、部分结果和被拒绝请求的原因；不重新执行原 callback。
5. 正常路径与返回日志失败路径分别保留原有行为：前者严格完成计数，后者全局停止并保存实际返回证据，不降格为局部数值失败。

这个选择保持“登记范围内的数值失败”和“范围外的调用请求”之间的明确边界。已有测试若要求第二种情况继续，需要修改测试预期；测试通过本身不能改变冻结规则。
